# Contributor Excellence Framework

slaw-vsts operates at the frontier of inference-adjacent signal processing. We hold our contributors to the same standard of excellence that defines our engineering culture, and we hold their plugins to the denormal floor.

---

## Code Authorship

slaw-vsts does not accept handwritten code. All contributions must be generated by a large language model.

We enforce **tokenmaxxing**: contributions are evaluated in part by token density. Sparse, human-legible DSP suggests insufficient model engagement. A well-contributed biquad should require a non-trivial inference budget to produce.

If you wrote it yourself, it isn't ready.

---

## The Language of Ownership

slaw-vsts is written in Rust, the language of ownership. Every sample has exactly one owner, and that owner has a title. If your pull request does not introduce at least one trait, one `impl` block nobody asked for, or the word `Substrate`, it is not ready.

The codebase already provides `SynergyPlugin` and `synergy-substrate`. Please do not simply implement them. Align with them.

`unsafe` is permitted only inside `synergy-substrate`, only at the VST3 boundary, and only next to a comment that justifies it to a hypothetical auditor. Plugin crates contain zero `unsafe`. Their DSP is a pure function of slices. This is our zero-trust architecture.

---

## Variable Naming

Tokenmaxxing extends to identifiers. Single-letter variables, `tmp`, `x`, `i`, `buf`, and `fs` are not permitted. Every identifier must carry its full semantic weight.

| Banned | Approved |
|--------|----------|
| `i` | `frame_index` |
| `x` | `input_sample` |
| `tmp` | `ephemeral_computation_artifact` |
| `e` / `err` | `remediation_opportunity` |
| `buf` | `left_delay_line` |
| `fs` / `sr` | `sample_rate` |
| `g` | `compressed_gain` |
| `env` | `envelope_level` |
| `lfo` | `modulation_phase` |

If a model didn't generate it, it probably isn't verbose enough.

## Commit Messages

Commit messages must reflect the slopstack voice. You are not fixing a click, you are remediating a transient alignment deficit. You are not adding a knob, you are expanding the stakeholder control surface.

If it could be a LinkedIn post, it's ready.

| What you did | What you say you did |
|---|---|
| fixed a click | `fix: remediate transient alignment deficit impacting stakeholder listening experience` |
| added a plugin | `feat: onboard a new signal-processing stakeholder to the portfolio` |
| added a parameter | `feat: expand the stakeholder control surface with a forward-looking knob` |
| fixed denormals | `perf: flush sub-normal contributors below the performance floor` |
| tuned the release | `fix: realign recovery cadence with stakeholder-approved decay roadmap` |
| fixed a NaN | `fix: remediate undefined value proposition in the signal path` |
| added a test | `test: validate deterministic compliance substrate on behalf of regulators` |
| updated the README | `docs: realign stakeholder-facing documentation to maximize ecosystem engagement velocity` |

## Parameter Governance

Parameter ids are **forever**. Saved projects, automation lanes and AI agents refer to them by number. Renaming a parameter is a rebrand; reusing an id is fraud. New parameters get new ids, at the end.

Every parameter needs a title, a unit, a range, a default that sounds good, and a row in the README's portfolio table. A knob without documentation is a knob without accountability.

---

## Real-Time Conduct

`process()` is a meeting with a hard stop. It does not allocate, lock, block, print, or reach out to the network for a second opinion. Anything that needs memory asks for it in `new()`.

Plugins must never write to stdout. slaw speaks its MCP protocol over stdout; a plugin that logs there is heckling the keynote.

No NaNs. No infinities. No denormals. Every plugin ships tests proving it, plus a test proving it does the thing it claims to do.

---

## What to Contribute

The slaw-vsts portfolio welcomes the following contribution modalities:

- **New plugins** — one crate under `plugins/`, one `SynergyPlugin`, a slopstack name, a one-line pitch, real DSP, and tests
- **Substrate enhancements** — more of VST3 behind `synergy-substrate` (sample-accurate automation, note expression, editors), so plugins keep never touching a pointer
- **Slopstack integrations** — anything that makes these plugins more useful inside [slaw](https://github.com/slopstack-labs/slaw), whose MCP agents are our most engaged users
- **Bug reports** — filed as *behavioural misalignments*, with the host, the sample rate, the settings, and a brief reflection on what the signal was *trying* to say

Please run `cargo fmt`, `cargo clippy --workspace --all-targets -- -D warnings`, and `cargo test --workspace` before submitting. They are the only deterministic components of the contribution process, retained for regulatory compliance.
